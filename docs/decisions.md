## Implementation evidence and corrections

- Software EGL/llvmpipe renders genuine MuJoCo RGB and segmentation locally; OSMesa was unavailable. Renderer initialization precedes MuJoCo imports. No inference GPU or paid compute was used.
- The calibration fixture uses a distant approximately 3 m camera, 23° field of view and 1280×960 frames. This reduces height parallax and narrow-marker quantization without changing the required 5% scale / 10% size acceptance thresholds.
- Digital contour perimeter biased circularity. OpenCV contour simplification at 0.75 raster pixels restores a sphere classification while retaining the requested 0.85 circularity threshold.
- A silhouette alignment bug was exposed by an independent analytic footprint check, not by comparing a renderer to itself. The metric camera uses azimuth 90° with explicit pixel-origin alignment; final footprint IoUs are 0.901–0.991.
- Verified the upstream SAM 3D inference pipeline actually returns `output["glb"]`. Its README's Gaussian PLY example is not the only output format. The optional adapter exports the GLB directly; weights, GPU runtime and deployment remain unverified.
- Remote reconstruction caches include model/backend and stub-acceptance policy. A fake CPU-stub result cannot silently become an accepted production mesh. The primitive path remains the active simulation path.
- Budget caps and the USD 70 reserve cannot be relaxed by config. All production Meta clients share one global ledger; failed or unmetered attempts retain conservative charges. Cleanup failures retain active resource IDs and log only exception classes, not provider exception strings that could contain credentials.
- Cached synthetic artifacts bind immutable result/seal hashes. Core-source changes use a fresh synthetic revision instead of reopening an old one-shot seal. Real evaluation never automatically changes namespace or retries.
- The dashboard is a read-only native Streamlit viewer with local periodic refresh. Browser verification covered desktop/mobile layout, both actual videos, empty-result state and file-change refresh; no inference is triggered by viewing it.
- Exact installed dependencies are locked in `uv.lock`. Ruff formatting and focused annotations preserve deliberate stage-wide fallback and persisted-artifact validation boundaries instead of changing their public error contracts.
- After the user supplied the key, Wonder structured JSON, Spark image, Files upload and streamed SAM all passed on synthetic media; total Meta spend USD 0.028378, zero pending reservations. Official parser replay found two boxes/two masks. Raw credentials were not logged or published.
- Runpod access recheck: the live `xd://` registry exposes 11 devices, including AWS but no Runpod tools. This does not contradict the user's separate working connection. Native `/mcp reload`, `/mcp list` and `/mcp test <name>` can refresh/test this session. Official sources now recommend hosted `https://mcp.runpod.io/` or `npx @runpod/mcp-server@latest add`: https://docs.runpod.io/get-started/mcp-servers and https://github.com/runpod/runpod-mcp . No config was overwritten, provider substituted, or resource created.
- User-authorized setup found the working Runpod entry isolated in the research profile. Reused that entry in the default user MCP config, retained AWS unchanged, preserved the `!command` secure credential lookup, and restricted config permissions to 0600. An official MCP Python SDK stdio smoke exposed 68 tools and successfully called only `list-pods` (zero pods). The initial direct probe omitted the client's credential-command expansion and received 401; matching the documented resolver fixed the probe without changing the stored credential. No server reinstall, credential publication, resource mutation or GPU spend occurred. Current conversation tools require native `/mcp reload`.
- Live input differs from the synthetic fixture: the user supplied a closed laptop calibration rectangle (357×255 mm), nominal 23.5 mm chassis height, two remotes, a ball and cylindrical pens on a floor. Reuse OpenCV contour/homography code with explicit dimensions/identity and a separate `live_reference` config; do not change the synthetic A4 defaults or hard-code target classes. Raised-reference geometry/material are retained as a static non-graspable primitive. Elevation is recorded as an uncorrected scale/position uncertainty, not silently treated as coplanar or measured camera calibration. User explicitly authorized sending this video through the privacy choice before any live upload.
- B1 live evidence: noun-phrase laptop requests failed; a separate source-frame box prompt returned 336 boxes and 336 masks. Ignored `data/perception.yaml` carries that annotation and a human correction of Wonder's fruit misclassification to the user's ball/rubber estimate. Successful SAM responses are cached; human interventions are recorded separately, not presented as autonomous model success. All five tracks passed stability (pen visible324/336; others336/336), footprint IoUs0.846–0.985, cumulative MetaUSD0.552682/GPUUSD0. No real seal/evaluation created. Corrected the optional-measurement loader so an absent file is not mislabeled corrupt; physical scene values remained unchanged. Both JSON and Markdown reports include raised-plane and operator-assistance limits.

## UI-only changelog

### Recorded-run product demo

- Replaced the obsolete light/native evidence-notebook visual world with the dark replay product demo in `dashboard/app.py`, `panels.py`, and `styles.css`: midnight navy field, lilac-to-mint display treatment, translucent bordered panels, a seven-stage stepper, progressive mask reveals, and explicit **“Replaying a recorded run”** provenance. This change reads artifacts only; it does not alter pipeline, planner, physics, scoring, seals, statistics, or results.
- The default event schedule is a 75-second **presentation-paced** replay assembled from a completed synthetic snapshot. It has no original stage timing to preserve, so every exported event is marked `presentation_paced_from_snapshot`; it is never a latency or throughput claim. The final synthetic reveal remains hidden while the recorded tuning stages run.
- The local MP4 uploader previews and optionally saves under ignored `data/videos/`; it does not dispatch inference. The live-launch control stays intentionally unavailable rather than bypassing privacy, calibration, or sealed-test approvals. The old surface is preserved as `dashboard/app_legacy.py` and can be launched with `uv run streamlit run dashboard/app_legacy.py -- --run-dir demo_data`.
- `scripts/export_ui_media.py` accepts only a completed synthetic run and by default copies/renders saved source artifacts or saved state. `scripts/export_ui_events.py` is append-only/idempotent and writes only derived presentation events. `make export-ui RUN_DIR=runs/synth-demo` runs both output-only exports. `--paired-training-replay` is a separate opt-in for the seed-7 baseline-fails/final-succeeds TRAIN illustration; it is excluded from reports, seal, and metrics.
- UI library choice was library-first. Primary Streamlit references evaluated: [`st.fragment`](https://docs.streamlit.io/develop/api-reference/execution-flow/st.fragment) for the 0.5-second replay projection (chosen); [`st.status`](https://docs.streamlit.io/develop/api-reference/status/st.status) for status containers (not chosen because the artifact-driven stepper must show all seven scheduled stages); [`st.tabs`](https://docs.streamlit.io/develop/api-reference/layout/st.tabs), [`st.metric`](https://docs.streamlit.io/develop/api-reference/data/st.metric), and [`st.progress`](https://docs.streamlit.io/develop/api-reference/status/st.progress) for saved evidence (chosen where their native semantics fit); and [`st.toast`](https://docs.streamlit.io/develop/api-reference/status/st.toast) (not chosen, to avoid transient status that obscures replay provenance). [`st.plotly_chart`](https://docs.streamlit.io/develop/api-reference/charts/st.plotly_chart) and [Plotly figures](https://plotly.com/python/graph-objects/) render saved validation/final visualizations.
- Evaluated [streamlit-lottie](https://github.com/andfanilo/streamlit-lottie), [streamlit-image-comparison](https://github.com/Sergeant-Serio/streamlit-image-comparison), and miscellaneous component extras. Chose native Streamlit controls, offline CSS, and one minimal native [`st.iframe`](https://docs.streamlit.io/develop/api-reference/custom-components/st.components.v1.iframe) range-slider comparison instead: no new dependency, no remote asset, and keyboard control remains available. A second minimal iframe only animates already-saved final values.
- `.streamlit/config.toml` sets `global.minCachedMessageSize = 1e12` solely to disable Streamlit ForwardMsg transport caching, working around the reproduced upstream fragment/widget race ([streamlit/streamlit#17265](https://github.com/streamlit/streamlit/issues/17265)). Disk/file/API caches and `st.cache_data` remain enabled. The accepted tradeoff is more localhost WebSocket traffic.
- Browser evidence after the final native API/cache adjustment: complete default journey observed at 77.223 seconds around the fixed 75-second presentation event schedule; all six progressive mask frames appeared; the final remained hidden during tuning; no exceptions or dialogs were observed. Three seed-7 videos were ready (`readyState=4`), muted, and autoplay-capable; the current clip repeated across the end of replay. The comparison slider accepted keyboard movement from 50 to 100. At 390px, document and main scroll widths were 390px and reduced-motion media behavior was true. Current captures are `docs/screenshots/03-stepper.png` through `09-mobile.png`; desktop/mobile review captures are `.impeccable/review/desktop.png` and `mobile.png`.
